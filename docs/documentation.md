# Documentation your users and your team can actually follow

For software companies whose runbooks, setup guides and knowledge base articles are out of date, scattered, or living in one engineer's head.

[Ask about a documentation project](mailto:hello@johnsontechnicalsystems.com?subject=Documentation%20project){ .md-button .md-button--primary }

## What I write

- Runbooks and troubleshooting guides
- Standard operating procedures and configuration guides
- Knowledge base articles and end-user how-to guides
- Cleanup and restructuring of existing documentation

## How I write

- **Task first.** Each procedure says what it achieves and what it doesn't cover, then gives numbered steps in the order they are done.
- **Verification is part of the procedure.** It ends with checks that prove it worked.
- **Failure modes from real faults.** Symptom, cause and fix tables record what actually goes wrong.
- **Docs as code if you want it.** Markdown in Git, changes reviewed through pull requests, with automated checks before publishing. This site is built that way.
